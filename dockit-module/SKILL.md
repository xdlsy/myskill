# 模块文档化

## 概览

为单个模块生成可视化蓝图文档，基于 **Mermaid C4 Component 图**，描述模块内部组件、对外接口、依赖关系和关联流程，输出到 `docs/knowledge/modules/` 目录。

适用于：
- 为已有知识库新增一个模块文档
- 对某个模块进行独立文档化（不需要全量构建知识库）
- 作为 `dockit-knowledge` 步骤 3 的增量补充

## 前置条件

- **推荐**：`docs/knowledge/flows/` 已存在（模块文档会链接到关联流程）
- **推荐**：`docs/knowledge/decisions/` 已存在（模块文档会链接到关联 ADR）
- **最低要求**：了解模块的内部组件结构和对外接口

## 工作流

### 步骤 0：发现（Discovery）

收集待文档化模块的信息。支持两种模式：

**独立模式**——向用户一次性收集：
1. **模块名称**（中文短句，如"TCP 服务器"、"浏览器 SDK"）
2. **所属系统**（系统名称，用于文档头部面包屑）
3. **模块类型**（应用服务 / 基础设施 / 数据存储 / SDK / 配置）
4. **技术栈**（语言、框架、关键依赖）
5. **职责**（一句话描述 + 可选业务域标签）
6. **内部组件清单**：

| 组件名 | 技术/类型 | 职责描述 |
|--------|----------|----------|
| `TcpServer` | Netty | 接收客户端 TCP 连接 |
| `CertificateManager` | Java Security | TLS 证书管理 |

7. **对外接口**：

入站接口（我提供的）：

| 接口 | 协议 | 调用方 | 所属流程（可选） |
|------|------|--------|-----------------|
| `POST /api/browser/create` | HTTP REST | API 网关 | 浏览器创建 |

出站依赖（我调用的）：

| 接口/中间件 | 提供方 | 用途 | 所属流程（可选） |
|------------|--------|------|-----------------|
| `BrowserService.create()` | browser-proxy | 创建浏览器实例 | 浏览器创建 |

8. **关联流程**：该模块参与哪些核心流程？在每个流程中的角色和步骤？

9. **关键设计决策**：该模块有哪些特有的架构决策？（若有对应 ADR，提供编号和链接）

**管道模式**——从已有产物推断：
- 读取 `docs/knowledge/flows/INDEX.md` 获取该模块参与的流程
- 读取相关流程蓝图获取模块在流程中的角色和调用链
- 读取 `docs/knowledge/decisions/INDEX.md` 获取关联 ADR
- 读取 `docs/knowledge/modules/INDEX.md` 了解已有模块结构
- 将推断结果展示给用户确认和补充

> **交互原则**：一次问清楚所有信息，不要一个问题一个问题地追问。如果用户一次性提供了完整信息，直接跳入生成步骤。

### 步骤 1：生成模块蓝图

生成 `docs/knowledge/modules/<module-name>.md`。

模板：`templates/module-blueprint.tmpl.md`

每份模块蓝图包含：

1. **元数据行**：所属系统、模块类型、技术栈
2. **职责描述**：一句话描述 + 可选业务域
3. **C4 Component 图**（Mermaid `C4_Component`）：模块内部组件及其交互
4. **对外接口**：
   - 入站接口表（协议、调用方、所属流程链接）
   - 出站依赖表（提供方、用途、所属流程链接）
5. **关联流程表**：流程名、角色、步骤
6. **关键设计决策**：链接到关联 ADR
7. **导航尾部**：返回模块总览和蓝图首页的链接

> **规模控制**：
> - 如果模块内部组件 ≤ 5 个，生成完整 C4 Component 图
> - 如果模块是纯 CRUD 或纯配置模块，可跳过 Component 图，仅保留接口和流程表
> - 每条对外接口应尽量关联到具体流程文档

### 步骤 2：更新模块索引

如果 `docs/knowledge/modules/INDEX.md` 已存在，将新模块追加到：
- **模块清单**表：新增一行
- **模块依赖全景**图（Mermaid `graph LR`）：新增节点和边

如果 `INDEX.md` 不存在，使用模板 `templates/module-index.tmpl.md`（来自 `dockit-knowledge`）创建新索引。

### 步骤 3：确认与回写

1. 展示生成的模块文档给用户确认：
   - "模块的内部组件划分是否准确？"
   - "对外接口列表是否完整？"
   - "出站依赖是否正确？"
   - "关联流程是否覆盖该模块参与的所有流程？"

2. 如果 `docs/knowledge/AGENTS.md` 存在，询问是否需要更新其中的模块清单。

## 生成后

展示生成结果概览：

```
📄 模块文档已生成：

docs/knowledge/modules/
├── INDEX.md                       # 模块总览（已更新 / 新建）
└── {module-name}.md               # C4 Component 图（{N} 个组件，{M} 个接口）
```

确认重点：
- C4 Component 图是否准确反映内部组件和交互
- 接口表是否完整（入站 + 出站）
- 关联流程的交叉引用是否有效
- ADR 链接是否正确

## 子 Agent 模式

当被 `dockit-knowledge` 作为子 Agent 调用时：
- **跳过步骤 2（INDEX.md 更新）**：由主 Agent 在所有模块子 Agent 完成后统一汇总生成
- **跳过步骤 3（AGENTS.md 回写）**：由主 Agent 在步骤 6 统一处理
- 仅执行步骤 0（发现）和步骤 1（生成模块蓝图），专注于单模块文档的创建
- 主 Agent 会通过 prompt 携带完整的模块上下文，减少交互轮次

## 幂等性

如果目标模块文档 `docs/knowledge/modules/<module-name>.md` 已存在：
- 不静默覆盖
- 展示已有内容摘要，询问处理策略：
  - **跳过**：保留现有
  - **覆盖**：完全重新生成
  - **合并**：保留现有内容，仅更新指定的图/表格/接口
- 支持增量更新：可以只更新 Component 图或只补充对外接口

## 文件约束

- 模块蓝图 ≤ 150 行
- C4 Component 图组件数 ≤ 15（过多考虑拆分子模块）
- Mermaid 代码块正确标注语言（`mermaid`）
- 所有交叉引用使用相对路径链接
- 文件名使用小写 + 连字符（如 `tcpserver.md`）
