## 1. 概述

一个个人 skill，解决「工作一天后没精力整理，但又不记就忘了」的问题。离岗前敲一个命令，把当天工作脑暴式丢进来，skill 自动整理成结构化日报并归档；到周/月/半年/年边界时顺带汇总成对应报告。

核心价值：**用最低的输入成本（一段脑暴文字），产出可检索、可汇总、可复盘的工作记录体系**。

## 3. Skill 身份与调用

- **名字**：`work-log`
- **位置**：`/Users/lsy/skills/work-log/`
- **触发描述**（frontmatter `description`）：
  > Use when ending the workday to log what you did (takes a brain-dump and structures it), or to generate a weekly/monthly/half-year/annual work report.
- **调用方式**：
  - `/work-log` + 当天工作脑暴文字 → 生成/追加当天日报
  - `/work-log 2026-07-20` → 补写指定日期的日报
  - `/work-log weekly` / `monthly` / `halfyear` / `yearly`（可带日期，如 `weekly 2026-W28`）→ 手动生成周期报告

## 5. `memory.md` 结构

三块：

1. **配置**：归档根目录（默认 `~/worklog/`）、语言（中文）、边界定义（周=周一~周日、半年=自然半年）、时区假设。
2. **用户习惯**：写作详略偏好、常用项目名/团队成员、常见工作类型分类。**skill 用几次后会主动把反复出现的项目名补进来**——这是它「记住你」的地方。
3. **状态游标**：`last_generated: { weekly: 2026-W29, monthly: 2026-06, halfyear: 2026-H1, yearly: 2025 }`，用于判断「是否已有本周周报」、避免重复生成。

## 6. 日报生成流程

用户敲 `/work-log` + 脑暴文字，skill 依次：

1. 读 `memory.md` 拿配置/习惯/游标。
2. 算出今天的日报路径；**若今天已有日报 → 先问「追加 / 覆盖 / 编辑」，绝不静默覆盖**。
3. 把脑暴内容拆成若干条「核心工作」，每条按四维展开：
   - **内容** — 做了什么
   - **解决了什么问题**
   - **已经产生了什么结果**
   - **对后续的影响**
4. 末尾加 **今日小结**（2–3 句概括）+ 元信息（日期、覆盖范围、数据来源 = 用户脑暴）。
5. 写入日报文件（按 `templates/daily.md`）。
6. 若发现新习惯/项目名 → 回写 `memory.md`。
7. **边界检测**（见第 7 节）。

**日报样例**（`2026-07-23.md`）：

```markdown
# 2026-07-23 工作日报

## 核心工作

### 1. 订单服务接口超时排查
- **内容**：定位订单服务 P99 从 200ms 飙到 1.8s 的根因（连接池配置过小）。
- **解决了什么问题**：线上下单偶发超时（影响约 3% 订单）。
- **已经产生的结果**：连接池参数上调并灰度上线，P99 回落至 230ms，超时率 <0.1%。
- **对后续的影响**：沉淀一份「连接池容量评估清单」，后续新服务上线可直接套用。

### 2. …（第二条）

## 今日小结
集中解决了订单服务稳定性问题，顺带产出一份可复用的容量评估清单。

---
*覆盖范围：2026-07-23 | 数据来源：用户脑暴*
```

## 7. 周期报告：边界、时机、分层汇总

### 7.1 边界定义（默认，写在 `memory.md`，可改）

| 报告 | 周期 | 结束日 |
|---|---|---|
| 周报 | 周一~周日（ISO 周数） | 周日 |
| 月报 | 自然月 | 当月最后一天 |
| 半年报 | 1–6 月 / 7–12 月 | 6/30、12/31 |
| 年报 | 自然年 | 12/31 |

### 7.2 生成时机（三种，全覆盖）

- **顺带**：写日报时检测到今天撞上边界 → 一句话列出所有命中的周期并等确认。例：「今天是 7 月最后一天（也是周日），命中的周期：**周报 2026-W30** + **月报 2026-07**，要顺带生成吗？」
- **补漏**：边界当天没记（如周日没开电脑），下次写日报时检测「自上次该类报告之后，已有完整周期结束」→ 提示补生成。
- **手动**：`/work-log weekly`（可带日期）。

### 7.3 分层汇总（纯 markdown 也能撑住年报的关键）

上一层**只读下一层**，不读原始日报，避免上下文爆炸：

- **周报** ← 读本周 7 篇日报 → 按主题归并去重 → 本周核心工作 / 主要进展 / 遗留问题 / 下周关注
- **月报** ← 读本月周报（4–5 篇）+ 未被周报覆盖的零散日报 → 月度总结
- **半年报** ← 读该半年 6 篇月报 → 重大成果 / 趋势 / 关键问题
- **年报** ← 读 12 篇月报（或 2 篇半年报）→ 年度总结

每份报告都带元信息：**覆盖日期范围 + 数据来源（读了哪些文件）+ 生成时间**。报告是从源文件派生的，**随时可重新生成（覆盖）**。

## 8. 边界情况与错误处理

| 情况 | 处理 |
|---|---|
| 同一天多次记录 | 默认追加新一批「核心工作」，问是否合并进已有条目；**绝不静默覆盖** |
| 补写历史某天 | 正常写那天日报；若该天落在已生成的周/月报里 → 提示「该报告已过期，要重新生成吗？」 |
| 漏记录的天 | 报告只覆盖有记录的天，并在报告里点名「本周 7 天中 7/15、7/16 无记录」 |
| 脑暴信息不全 | 四维凑不齐时，能填的填、凑不齐的标「（待补充）」——**绝不编造结果或影响** |
| 目录不存在 | 首次写入自动建 `年/月/` 文件夹 |
| 首次运行 | `memory.md` 没有归档路径 → 问一次并存 |
| 边界当天没开机 | 下次写日报时补漏检测（见 7.2） |

## 9. 测试策略（writing-skills 的 TDD：subagent 压力场景）

用「不给 skill 时 agent 会怎样（基线失败）→ 给 skill 后是否合规」验证。压力场景（细节在实现计划阶段展开）：

1. 给一段杂乱脑暴 → 产出的日报每条工作都有完整四维、不编造、有今日小结
2. 已有日报的当天再记 → 必须先问再写，不静默覆盖
3. 喂不同「今天」日期（周日 / 月末 / 6·30 / 12·31 / 普通周三）→ 正确识别命中的周期；普通周三识别为「无」
4. 给一周 7 篇日报 → 周报覆盖全部主题、去重、点名漏记天
5. 月报读周报而非原始日报、年报读月报（验证分层汇总，防上下文爆炸）
6. 脑暴缺「结果」维度 → 该条标「待补充」而非瞎编

遵循 `writing-skills/testing-skills-with-subagents.md` 的方法执行。

## 10. 范围与非目标（YAGNI）

**不做**：
- 不做结构化数据存储（JSON/YAML）——四维提炼是判断活，结构化买不到什么，且更难手改。
- 不做前端/UI/看板——纯 markdown 文件，用任何编辑器看。
- 不做多用户/团队共享——个人 skill。
- 不做自动定时（cron 式）触发——靠用户离岗前手动敲命令；定时不是 skill 的职责（若需要定时，由 harness 的 cron/hook 机制另行配置，不在本 skill 范围）。
- 不做脚本（除非日后边界判断证明不可靠，再单独加一个边界检测脚本）。
