# 核心网软件研发 AI 落地蓝图（v1.0）

> **面向**：用 AI 做核心网软件的研发组织（非做 AI 产品的公司）。
> **目标**：把 AI/Agent 系统性嵌入"运营商/3GPP 需求 → 软件交付 → 运维"全流程，在**不牺牲五个 9、安全性与合规**的前提下拿到可度量的研发提效。
> **版本**：v1.0 草案 ｜ **日期**：2026-07-31 ｜ **状态**：待评审

---

## 0. 蓝图总览（一页纸）

### 北极星目标
**12–18 个月内，在不降低交付质量与安全水位的前提下，将核心网软件的"需求→交付"周期与一致性测试成本显著压缩，并沉淀一套可复用、可治理的 AI 研发平台。**

### 五条铁律（贯穿全蓝图）
1. **放大器原则**：AI 放大既有工程纪律。先夯实 review/测试/门禁/追溯，再上 AI——否则就是"加速制造技术债"（DORA 2025、CMU）。
2. **治理先行**：七项控制与质量门禁不达标，不扩张 Agent 使用面（88% 试点因此失败）。
3. **风险分层**：按代码/资产的风险等级，规定 AI 的自主度与验证手段——核心运行时设红线。
4. **人在环（Human-in-the-loop）**：AI 产出"快但远不完美"，关键环节人审 + 多重验证不可省。
5. **产品化思维**：把 AI 能力当"内部产品"长期运营，而非一次性项目；设专职 owner、有度量、有迭代。

### Roadmap 一览
| 阶段 | 时间 | 主题 | 关键产出 |
|---|---|---|---|
| **Phase 0** | 第 0–4 周 | 基线与准备 | 治理章程、风险分层模型、平台选型、试点立项、度量基线 |
| **Phase 1** | 第 1–3 月 | 单点突破（2 个旗舰试点） | 一致性测试用例生成 MVP、3GPP 需求解析 MVP |
| **Phase 2** | 第 3–6 月 | 平台加固 + 横向扩展 | 七项控制全量落地、Agent 平台、扩到 5–8 个团队 |
| **Phase 3** | 第 6–12 月 | 规模化与产品化 | 编码 Agent GA、运维 AIOps、能力外溢为产品 |
| **Phase 4** | 第 12 月+ | 持续运营与演进 | 专人运营、年度策略刷新、向 6G/Agent 化演进 |

## 2. 组织与治理基线（Phase 0 必须先行）

> 核心网是强合规、安全攸关领域。组织与治理不到位，技术再好也推不动。

### 2.1 组织结构：AI 工程效能组（AI EngProd / 内部 CoE）

采用 **Hub-and-Spoke**（中心 + 业务线）模型：
- **中心（AI EngProd 组，3–6 人起）**：制定章程与红线、建设平台、评估选型、沉淀最佳实践、度量与汇报。设**专职 AgentOps / AI 工程效能负责人**（56% 成功规模化的企业都设了专职 owner）。
- **Spoke（各产品线/网元团队）**：在本团队落地场景、反馈数据、提名新用例。每团队指定 1 名"AI Champion"。
- **治理委员会**（安全 + 架构 + 质量法务 + EngProd 负责人）：评审红线、处置事件、审批新场景。

### 2.2 七项不可妥协控制（落地清单）

| 控制 | 落地动作 | 责任 | Phase |
|---|---|---|---|
| 身份与 SSO | 每个 Agent 会话映射具名自然人；SSO/SCIM 对接 | IT/安全 | P0/P2 |
| 审计日志接 SIEM | 文件访问/shell/PR/API 全进 SIEM，留存满足合规 | 安全/平台 | P2 |
| 密钥扫描 | 每个 Agent PR 合并前强制扫描，**基础设施层强制** | 平台 | P1 起 |
| PR 策略门 | Agent PR 与人工 PR 同等过门：owner review/覆盖率/lint/SAST/密钥；标签 `agent:*` 回溯会话 | 各团队 | P1 起 |
| 沙箱隔离 | Agent 执行 shell/装包/联网须隔离；生产基线 MicroVM 独立内核 | 平台 | P2 |
| 许可证治理 | 可接受许可清单 + 预合并扫描 | 法务/平台 | P2 |
| 事件响应 Runbook | Agent 触发事件：谁 paging、如何吊销权限、定位回滚、向审计报告 | 安全+SRE | P2 |

### 2.3 平台选型原则（不指死产品，给类别）
- **全仓索引/长上下文**：大型 C/C++ 代码库的头号挑战是上下文，必须支持仓库级语义索引（否则建议"浅而错"）。
- **私有化/数据不出**：核心网源码与运营商数据不得外流——优先自建/VPC/BYOC，模型可选自托管或企业版。
- **可观测与 eval 内置**：tracing、成本/token、审计、回归评估集成。
- **可治理**：支持 RBAC、网络出站管控、与现有 CI/Git 集成。
- **多模型路由**：避免单一供应商锁定（业界 >75% 组织多模型）。

## 3. 风险分层模型（蓝图的核心工件）

> 把所有"会被 AI 碰到"的资产按风险分四档，每档明确**自主度 + 必需验证 + 责任人**。这是安全攸关软件落地的"红绿灯系统"。

| 风险档 | 资产类型（核心网示例） | AI 自主度 | 必需验证手段 | 责任人 |
|---|---|---|---|---|
| 🟢 **L1 放手** | 测试脚本、工具脚本、CI 配置、文档、Mock、Lab 自动化、内部脚手架 | **高**（Agent 大胆生成） | 基本门禁 + 人抽样审 | 工程师 |
| 🟡 **L2 起草+强审** | 控制面云原生代码、SBI/OpenAPI 接口、配置管理、重构建议、bug 修复（非关键路径） | **中**（Agent 起草，强制专家 review） | 全门禁 + 测试 + 架构 review | 模块负责人 |
| 🟠 **L3 仅辅助** | 复杂协议逻辑、并发/资源管理、性能相关、对外接口契约 | **低**（AI 仅辅助审阅/分析/补测试，不自动生成核心逻辑） | 多重验证（见下） + 资深专家双审 | 架构师 |
| 🔴 **L4 红线** | 数据面/转发面、协议状态机核心、鉴权与安全、内存关键路径、密码学、确定性时序 | **禁自动生成**（仅允许 AI 做只读分析/解释/查资料） | 形式化/模型检查 + 一致性 conformance + 代码评审委员会 | 治理委员会 |

**L3/L4 的"多重验证"组合**：类型系统/编译器护栏 + 静态分析(SAST/ sanitizer) + 单元/集成测试 + 协议一致性 conformance + （关键处）形式化验证/模型检查 + 人工双审。原则：**"可验证才采纳，不可验证不进主干"。**

> 每个产品线须在 Phase 0 把自己的代码资产**逐目录/逐模块**映射到此表，经治理委员会签字，作为 Agent 使用红线。**这张表是动态的**，随成熟度每季度复审。

## 4. 分阶段路线图（含里程碑与退出标准）

### Phase 0 — 基线与准备（第 0–4 周）
- **目标**：把"地基"打好，试点可启动。
- **关键举措**：成立 AI EngProd 组与治理委员会；发布《AI 研发使用章程》（铁律 + 红线）；完成风险分层模型（第 3 节）并签字；平台选型 RFP；选定 2 个旗舰试点与试点团队；建立度量基线（PR 吞吐/缺陷率/一致性通过率/静态问题趋势/MTTR）。
- **产出**：章程 v1、风险分层表、选型决定、试点立项书、度量基线。
- **退出标准**：①章程与红线发布并培训；②至少 1 个团队完成风险分层映射；③度量基线可采集；④试点立项获批（含目标 KPI）。

### Phase 1 — 单点突破：2 个旗舰试点（第 1–3 月）
- **目标**：用最小可行方案验证最高 ROI 场景，拿到"真提效"证据。
- **旗舰 A：AI 一致性测试用例生成**（见 §5，最高 ROI）
- **旗舰 B：3GPP 需求解析与追溯**（见 §5）
- **辅以快赢**：代码审查助手、文档/接口脚手架（低风险、即装即用）
- **退出标准**：①A 试点用例编写时间下降 ≥40%、人审采纳率 ≥60%、无误判放过；②B 试点需求条目抽取准确率达标、追溯可建；③未出现安全/质量事故；④度量数据持续采集。

### Phase 2 — 平台加固 + 横向扩展（第 3–6 月）
- **目标**：把试点经验沉淀为平台，治理全量就位，受控扩展。
- **关键举措**：七项控制全量落地；建 Agent 平台（沙箱、审计、eval、模型路由）；编码 Agent 在 L1/L2 资产上铺开；扩展到 5–8 个团队；建立"试点复盘 → 平台能力"的沉淀管线。
- **退出标准**：①七项控制通过安全审计；②≥5 团队稳定使用、无重大事件；③编码 Agent PR 占比与采纳率达标；④静态分析问题/复杂度**未劣化**（守住 CMU 的 +30%/+40% 红线）。

### Phase 3 — 规模化与产品化（第 6–12 月）
- **目标**：GA 化、覆盖全 SDLC、能力外溢。
- **关键举措**：编码 Agent 在 L2 资产 GA；测试生成从单协议扩到多协议/多网元；CI/CD Agent（误配检测、回滚预警）；运维 AIOps（5G 核心 PCAP 故障检测 + 3GPP 接地根因）；评估"AI 能力做成产品卖点"的可行性。
- **退出标准**：①端到端周期压缩达成目标；②一致性测试成本显著下降；③AIOps 在实验室/现场降 MTTR；④产品化提案通过评审。

### Phase 4 — 持续运营与演进（第 12 月+）
- 专职运营、年度策略刷新、季度红线复审；向 6G/Agent 化架构演进；跟踪标准（Ericsson 定调"Agent 实现不被标准化"，可自主迭代）。

## 5. 两个旗舰试点详案（Phase 1 直接可启动）

### 旗舰 A：AI 一致性测试用例生成 ⭐最高 ROI

**问题**：核心网一致性/IOT 用例数以万计，手写与维护成本极高。

**对标**：IETF《AI 辅助网络协议测试》五组件流水线 + L0–L5 自动化分级（[IETF draft](https://www.ietf.org/archive/id/draft-cui-nmrg-auto-test-00.html)）。目标把选定协议从当前（多为 L1–L2）推到 **L3（条件自动化）**。

**试点范围（建议窄口进入）**：选 **1 个协议 + 1 个网元的 1 个流程**（例：SMF 的 PFCP 会话建立，或 AMF 的 NGAP 注册流程）。先跑通"规范→用例→脚本→执行→反馈"全链路，再扩。

**参考架构**：
```
3GPP TS/RFC ──→ ①协议理解(NL→结构化: 字段/FSM/消息序列)
                      ↓
人类意图/覆盖目标 ──→ ②用例生成(正例+负例/fuzz) ──→ 专家审核
                      ↓                          (规格驱动，防循环验证)
                 ③脚本+DUT配置协同生成(RAG检索历史模式) ──→ 语法/语义校验+沙箱dry-run
                      ↓
                 ④批量执行(测试仪+DUT) ──→ ⑤报告分析/根因假设/用例修订(闭环)
```

**关键防错**：
- **防循环验证**：测试须对齐"规范需求"而非"当前实现"；用独立黄金用例集做交叉验证。
- **人确认异常**：L3 起人须确认"标记的失败是否真的是协议违规"。
- **概率性兜底**：LLM 产出全过沙箱 dry-run + 语义校验。

**8 周计划**：
| 周 | 动作 |
|---|---|
| 1–2 | 选定协议/流程；准备规范文本与黄金用例；搭最小流水线（①②） |
| 3–4 | 接脚本生成③与执行④；跑首轮；建反馈闭环⑤ |
| 5–6 | 扩用例覆盖（正/负例）；调优；人审流程上线 |
| 7–8 | 度量评估；复盘；决定是否进入 Phase 2 扩展 |

**度量目标（退出标准）**：用例编写时间 ↓≥40%；人审采纳率 ≥60%；覆盖的正/负例数；无误判放过的真实缺陷。

---

### 旗舰 B：3GPP 需求解析与追溯

**问题**：上千页规范、跨版本 gap、需求-测试追溯难建。

**试点范围**：选 **1 个 TS + 1 次版本升级**（例：Release 17→18 对某网元的影响）。

**流程**：
1. AI 解析 TS → 抽取**消息序列 / 状态机(FSM) / 字段 / 必选可选行为 / 约束**；
2. 生成结构化需求条目 + 用户故事；
3. 建**"3GPP 条款 ↔ 需求 ↔ 既有用例"双向追溯**；
4. **跨版本 gap 分析**：变更点、受影响网元/用例、回归建议。

**防错**：规范歧义处 LLM 最易错——专家必核验 FSM 与必选行为；追溯链需人工抽检。

**度量目标**：需求条目抽取准确率；追溯可建比例；gap 分析召回率；需求周期缩短。

## 6. 度量体系（防"假提效"）

> 必须双轨：**效率指标 + 质量防劣化指标**。没有质量护栏的提效是负债。

| 维度 | 指标 | 警戒线 |
|---|---|---|
| **效率** | PR 吞吐、需求→交付周期、用例编写时间、MTTR | 周期 ↓ 目标值 |
| **质量（防劣化）** ⚠️ | 静态分析问题率、代码复杂度、变更失败率、缺陷逃逸率、一致性通过率 | **不得上升超基线**（守住 CMU 红线） |
| **采纳** | 活跃用户率、Agent PR 占比、人审采纳率 | 持续上升 |
| **安全** | 密钥泄露事件、SAST 高危数、Agent 异常网络行为 | 零容忍 |
| **业务** | 一致性测试成本、上市时间、（可选）产品化收入 | — |

**北极星**：**质量不劣化前提下的端到端周期压缩率**。

## 7. 组织、角色与文化

- **新角色**：AI 工程效能工程师 / AgentOps（建设平台与红线）、AI Champion（各团队布道与反馈）、规格/意图工程师（把需求写成可被 Agent 执行的规格）。
- **培训**：分层培训（红线、提示工程、人审规范、安全）；给固定学习时间（研究表明带动 +131% 采纳）。
- **文化**：**透明回应"AI 抢饭碗"顾虑**（带动 +125% 采纳）；强调"人转向判断与验证"。
- **⚠️ 防人才断档**：别把初级任务全自动化的速度快于"初级→资深"培养路径的重塑，否则团队头重脚轻、断档高级工程师补给。

## 9. 风险登记册（Top 风险与应对）

| 风险 | 影响 | 缓解 | 监控 |
|---|---|---|---|
| **质量劣化（技术债加速）** | 高 | 质量防劣化指标 + 门禁；守住 CMU 红线 | 静态问题/复杂度趋势 |
| **循环验证**（测试印证实现） | 高 | 规格驱动测试 + 独立黄金集 | 用例有效性抽检 |
| **密钥/源码/数据外泄** | 极高 | 私有化 + 出站管控 + 密钥扫描 + 沙箱 | SIEM 审计 |
| **核心运行时被自动生成污染** | 极高 | L4 红线 + 多重验证 + 委员会审批 | 红线违规告警 |
