# 流程文档化

## 概览

为单条核心业务流程生成可视化蓝图文档，基于 **Mermaid 时序图**，描述跨模块调用序列、参与模块和异常路径，输出到 `docs/knowledge/flows/` 目录。

适用于：
- 为已有知识库新增一条流程文档
- 对某条流程进行独立文档化（不需要全量构建知识库）
- 作为 `dockit-knowledge` 步骤 4 的增量补充

## 前置条件

- **推荐**：`docs/knowledge/modules/` 已存在（流程文档会反向链接到参与模块）
- **最低要求**：了解系统模块名称和流程调用链

## 工作流

### 步骤 0：发现（Discovery）

收集待文档化流程的信息。支持两种模式：

**独立模式**——向用户一次性收集：
1. **流程名称**（中文短句，如"浏览器实例创建"）
2. **流程类型**（同步请求 / 异步事件 / 定时任务 / 混合）
3. **触发条件**（谁/什么触发此流程？）
4. **流程目标**（一句话描述流程要达成什么）
5. **参与模块与步骤**（按顺序列出）：

| 步骤 | 模块 | 动作 | 关键输入/输出 |
|------|------|------|--------------|
| 1 | 网关 | 接收客户端请求 | `imei`, `imsi` |
| 2 | 适配器 | 查询实例配额 | `instance_count` |

6. **异常路径**（可选但推荐）：

| 异常点 | 触发条件 | 处理方式 | 影响范围 |
|--------|----------|----------|----------|
| 步骤2：配额不足 | `count >= limit` | 返回错误码 | 本次请求失败 |

7. **是否为分布式事务**（涉及多个模块的数据变更？若有，说明补偿/回滚策略）

**管道模式**——从已有产物推断：
- 读取 `docs/knowledge/modules/INDEX.md` 获取模块清单和链接
- 读取相关模块蓝图获取接口信息
- 读取 `docs/knowledge/flows/INDEX.md` 了解已有流程
- 将推断结果展示给用户确认和补充

> **交互原则**：一次问清楚所有信息，不要一个问题一个问题地追问。如果用户一次性提供了完整信息，直接跳入生成步骤。

### 步骤 1：生成流程蓝图

生成 `docs/knowledge/flows/<flow-name>.md`。

模板：`templates/flow-blueprint.tmpl.md`

每份流程蓝图包含：

1. **元数据行**：流程类型、触发条件、目标
2. **参与模块表**：步骤序号、模块名（含链接）、动作、关键数据
3. **Mermaid 时序图**（`sequenceDiagram`）：完整的跨模块调用序列，含 `autonumber`
4. **异常路径表**：异常点、触发条件、处理方式、影响范围
5. **关联模块摘要**：反向链接到参与的模块文档
6. **导航尾部**：返回流程总览和蓝图首页的链接

> **时序图注意事项**：
> - 参与者名称使用中文，与模块文档名保持一致
> - 标注关键的请求/响应数据
> - 异常分支用 `alt/else` 或 `opt` 块表示
> - 如果某步骤是异步的（消息队列/事件），用 `-->>` 虚线箭头 + Note 标注
> - 时序图 ≤ 30 个交互步骤，过多则考虑拆分流程

### 步骤 2：更新流程索引

如果 `docs/knowledge/flows/INDEX.md` 已存在，将新流程追加到：
- **核心流程清单**表：新增一行
- **流程-模块矩阵**：新增一行（若模块数量变化则同时新增列）

如果 `INDEX.md` 不存在，使用模板 `templates/flow-index.tmpl.md`（来自 `dockit-knowledge`）创建新索引。

### 步骤 3：确认与回写

1. 展示生成的流程文档给用户确认：
   - "时序图的调用链是否正确？"
   - "异常路径是否覆盖了主要的失败场景？"
   - "参与模块的步骤顺序是否准确？"

2. 如果 `docs/knowledge/AGENTS.md` 存在，询问是否需要更新其中的流程清单。

## 生成后

展示生成结果概览：

```
📄 流程文档已生成：

docs/knowledge/flows/
├── INDEX.md                       # 流程总览（已更新 / 新建）
└── {flow-name}.md                 # Mermaid 时序图（{N} 个步骤，{M} 个模块参与）
```

确认重点：
- 时序图是否准确反映调用链
- 异常路径是否覆盖主要的失败场景
- 交叉引用链接是否有效

## 子 Agent 模式

当被 `dockit-knowledge` 作为子 Agent 调用时：
- **跳过步骤 2（INDEX.md 更新）**：由主 Agent 在所有流程子 Agent 完成后统一汇总生成
- **跳过步骤 3（AGENTS.md 回写）**：由主 Agent 在步骤 6 统一处理
- 仅执行步骤 0（发现）和步骤 1（生成流程蓝图），专注于单流程文档的创建
- 主 Agent 会通过 prompt 携带完整的流程上下文，减少交互轮次

## 幂等性

如果目标流程文档 `docs/knowledge/flows/<flow-name>.md` 已存在：
- 不静默覆盖
- 展示已有内容摘要，询问处理策略：
  - **跳过**：保留现有
  - **覆盖**：完全重新生成
  - **合并**：保留现有内容，仅更新指定的图/表格/异常路径
- 支持增量更新：可以只更新时序图或只补充异常路径

## 文件约束

- 流程蓝图 ≤ 120 行
- 时序图 ≤ 30 个交互步骤
- Mermaid 代码块正确标注语言（`mermaid`）
- 所有交叉引用使用相对路径链接
- 文件名使用小写 + 连字符（如 `browser-create.md`）
