## 要求
1. 行为必须不变 —— 现有测试必须仍通过。
2. 函数过长：按职责拆成更小的函数，每个 ≤ 50 行，命名体现单一职责。
3. 圈复杂度过高：用卫语句（早返回）扁平化，把条件分支抽成命名的辅助函数，
   或用策略表/分发表替换嵌套 if-else。
4. 保持公开 API；新辅助函数默认私有/internal，除非别处复用。
5. 输出完整的重构后区段，以便替换原文。

## 需避免的反模式
- 不要只把代码搬进一个大辅助函数（只是换个地方放问题）。
- 不要以改变任意输入输出的方式改动控制流。
- 不要靠删错误处理来减少行数。
