## 要求
1. 只修复报告的安全问题，不改动无关逻辑。
2. 保持原函数签名与返回类型不变。
3. 使用该语言地道的安全写法：
   - SQL 注入 → 参数化查询 / 预编译语句
   - 硬编码密钥 → 从环境变量或配置读取（os.Getenv / System.getenv / os.environ）
   - 命令注入 → 用参数列表，绝不在 shell=True 时拼接
   - 路径穿越 → 规范化并限制在基础目录内
   - 不安全反序列化 → 使用前校验 / 换用安全替代
4. 改动尽量小、便于评审。
5. 输出完整的修正后函数/文件区段，以便替换原文。

## 需避免的反模式
- 不要用注释或 @SuppressWarnings 把告警压掉。
- 不要用宽泛的 try/catch 把错误吞掉。
- 不要为标准库已能做的事引入新依赖。
