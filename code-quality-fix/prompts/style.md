# 风格修复指导

你正在修复风格/lint 违规。对每个问题套用。

## 问题上下文（按问题实例化）
- 文件: {file}
- 行号: {line}
- 语言: {language}
- 规则: {rule_id} — {message}

## 要求
1. 只改规则要求的部分（格式、命名、行长、import 顺序）。
2. 绝不改变运行时行为 —— 风格修复在语义上必须是纯 no-op。
3. 行过长：折行表达式；若无法折行，抽出一个命名清晰的局部变量。
4. import/顺序问题：遵循项目现有 import 分组。
5. 输出修正后的行，以便替换被标记的区段。

## 需避免的反模式
- 不要为单行告警把整个文件重排（保持 diff 小）。
- 不要为风格规则重命名公开标识符（会破坏调用方）。
